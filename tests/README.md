# tests —— 文档守护的回归测试

这些测试**不影响主程序**：`docwarden.mjs` 依旧是零依赖的，跑工具本身不需要装任何东西。
只有要跑测试时才需要 `jsdom`。

## 前置准备

```bash
npm install           # 只装 jsdom，测试用
```

jsdom 已经装好了（`devDependencies`，约 21 MB）。**它只是测试用的**——
`docwarden.mjs` 本身依旧零依赖，把 `node_modules` 整个删掉也不影响工具运行。

## 跑测试

```bash
npm run test:all      # ★ 推荐：12 套全跑，自动起 / 收本地界面与假模型
```

手工跑也行，但要自己管好两个后台服务：

```bash
npm start             # 另一个终端：主服务（5 个套件会连 127.0.0.1:5173）
npm run fake-llm      # 另一个终端：假模型（notify 第一次调用故意 500，只有 test:retry 要它）
npm test              # 11 套，不含 test:retry
npm run test:retry    # 单独一个：重试是否真的只补失败项
```

> **为什么推荐 `test:all`**：手工跑完容易忘了收后台服务。而**没被收掉的那个进程会一直跑着
> 启动时载入的旧代码** —— 之后任何文件重命名都会让它静默失效，测试全红，
> 而报错是「找不到界面文件 xxx.html」，跟测试要验的东西毫无关系。这个坑真踩过一次。

| 脚本 | 验证什么 | 需要 |
|---|---|---|
| `test:freshness` | **指纹与状态只有一份实现**：认得旧算法指纹、不会误触发重新生成、旧状态文件可迁移 | 无 |
| `test:ci` | **CI 主线在真实 git 仓库里跑一遍**（`--mode audit`，不调模型）：旧文档不误判、确认保留、索引带确认列 | 无（需本地有 `git`） |
| `test:init` | **安装器**：真装一遍再验收 —— 产出齐全、幂等不冲掉人的配置、预演不落盘、引用模式不塞脚本、doctor 能发现配置腐烂与占位符没换、装完真能跑 audit | 无（需本地有 `git`） |
| `test:validate` | **人工确认命令**：候选可确认并署名、失效默认拒绝且指路 --force、--force 后源码指纹跟上当前代码、不产生 status.json、dry-run 不落盘 | 无（需本地有 `git`） |
| `test:selfcheck` | 界面内联脚本语法 + 新增元素/函数是否既声明又被引用 | 无 |
| `test:status` | **文档新鲜度的完整生命周期**（候选→已验证→失效→复原→作废） | 主服务 |
| `test:persist` | 刷新页面会不会白跑（会话留存） | 主服务 |
| `test:ui-status` | 「文档现状」这一栏在真实界面里能不能用 | 主服务 |
| `test:mcp` | **MCP 服务**：真实 stdio 协议握手、五个工具、状态随内容返回 | 主服务 |
| `test:leak` | **API Key 绝不落盘**：跑完整流程后把项目目录每个文件翻一遍 | 主服务 |
| `test:retry` | 重试是否真的只补失败项 | 主服务 + 假模型 |

注意：

- 除 `freshness`、`ci`、`init` 和 `selfcheck` 外都要连 `127.0.0.1:5173`。
  用 `npm run test:all` 就不用管这些 —— 它自己起、自己收。
- `test:retry` 依赖假模型的「首次失败」状态，**手工重复跑要先重启假模型**，
  否则 notify 的第一次调用额度已经用完，就不再失败了。
  `test:all` 每次都起一个全新的假模型，天然避开这点。
- `test:all` 发现 5173 / 5401 已被占用会**直接报错退出**，不会去杀你正在用的进程。

全部以 `process.exit(1)` 表示失败，可以直接接进 CI。

> 想复用别处的 jsdom 安装（不装 node_modules）：
> `JSDOM_PATH="file:///<jsdom>/lib/api.js" node tests/ui-retry.test.mjs`

## 为什么要留这套测试

因为踩过两次同类的坑：

1. 界面上写着「失败可在下一步单独重试」，但**代码里根本没有这个功能**——纯属声明而无实现。
2. 失败的模块不显示任何原因，用户只能看到一排「—」，完全不知道发生了什么。

这两种问题的共同点是：**看代码看不出来，静态检查也查不出来，只有真正跑一遍才会暴露。**
后来 `test:status` 又立刻抓出一个服务端解析 bug（`^key:\s*(.*)$` 里 `\s` 会吃掉换行，
导致空值字段吞掉下一行的内容）。所以这里保留的是能真实驱动的测试，而不是靠人工点。

## 各测试的关键设计

### `freshness-parity.test.mjs` —— 指纹与状态只有一份实现

这个测试是在「统一指纹与状态」那次改动里补的，守的是**一条会直接烧钱的规则**。

CI 流水线和工作台以前各写了一套指纹：算法不同（sha1 / sha256），连拼接方式都不同。
后果是同一个项目两边都会把对方的产出判成「源码变了」，然后全量重新生成 ——
**源码一个字没动，模型额度却跑掉了。**

测试逐条钉死：

- 工作台转发的是**同一个函数**（`F.fingerprintFiles === K.fingerprintFiles`），不是两份长得像的实现
- 两种历史算法（工作台的 sha1+长度前缀、CI 的 sha256 裸拼接）算出的旧指纹**都认得**，
  判定仍是「已验证」而不是「已失效」，并标记 `needsUpgrade`
- 就地升级指纹后，**确认和正文一字未动** —— 升级只是换个数字，不该碰内容
- 改一个源文件 → 必须变「已失效」；改回去 → 必须复原（内容哈希，不是时间戳）
- frontmatter 写入/读回往返一致，**陌生字段不被顺手删掉**
- 旧 `status.json` 里的确认能搬进文档头部；**正文变过的不予继承**
  （搬一份过期担保比不搬更糟，它会让 AI 以为有人核对过）
- **功能点怎么拆只有一处实现**（`splitFeature`）：全角冒号、半角冒号、以及写进
  frontmatter 的 ` :: `，三种都要认。这一节是因为实测踩到才补的 —— 见下面
  `init-smoke` 里「功能清单的解析」那条

不需要主服务，纯 Node 跑。

### `ci-smoke.test.mjs` —— CI 主线真的能跑

在临时目录里搭一个**真实 git 仓库**（`git init` + 一次提交），按 SETUP.md 说的方式摆放
`scripts/`、`.knowledge.mjs`、`src/`，然后跑 `--mode audit`。

`audit` 模式**不调用模型**，所以这个测试不花额度，随时可以跑。它要证明的是几件
「光看代码看不出来」的事：

- 脚本在真实仓库里**不崩**（`node --check` 只查语法，查不出未定义变量这类运行时错误）
- 造一份带**旧算法指纹**的文档 → 不被判成「代码已变更」，而是报告「指纹换代，就地升级」
- 升级后**人工确认（谁、什么时候）原样保留**，正文一字未动
- 再跑一次**不会反复报升级**
- 改一个源文件 → 这时才报漂移
- 生成的 `INDEX.md` 带「人工确认」列
- **`--root` 指向哪个仓库，文档就写进哪个仓库**（引用模式的前提：脚本在工具目录、
  仓库在别处）。这条要是坏了，文档会被写进工具仓库里 —— 而现场通常没人会发现
- **随包发出去的 CI 模板不许硬编码厂商**（共 30 条断言）。这些模板会被 `init`
  直接复制进使用者的仓库，所以它们和配置模板受同一条约束：不替使用者决定源码发给谁。
  曾经这里写着 `LLM_MODEL: gpt-4o-mini`（GitHub 三处、GitLab 一处）——配上一个空地址，
  使用者拿到的是一句莫名其妙的「模型不存在」，而不是「你还没配模型接口」。
  两个平台的机制不同，断言也分开写：GitHub 要显式 `env` 传密钥且校验它来自 secret；
  GitLab 的 CI/CD 变量是自动注入的，模板里**本来就不该**声明（重复声明会覆盖成空值），
  所以那边验的是「头部说明了必须建哪些加密变量」。

### `init-smoke.test.mjs` —— 安装器

`npx docwarden init` 是使用者走的第一条路径，它坏了就没有后面任何事。
所以这个测试不检验函数返回值，而是**真的装一遍再验收**，共 101 条断言。
最后一个场景会**真的调一次模型**（用一个跑在同进程里的假服务），
把「装好 → 生成 → 写出文档」这条链完整走通 —— 前面所有场景都没覆盖到那一段。

三条最容易出错、且出了错不容易发现的事：

- **幂等**：第二次 init 绝不能把人逐字改过的 `.knowledge.mjs` 冲掉。
  这是不可原谅的错误，所以专门钉死 —— 重跑一次，那个文件必须**一个字节都没变**，
  且报告「写入 0 个文件」；`.gitignore` 也不许重复追加。
- **预演**：`--dry-run` 必须一个字节都不写。测法是装到一个空目录里，然后逐个断言
  `scripts/`、`.knowledge.mjs`、`docs/decisions/` 都不存在。
- **装完真能跑**：在装好的项目里 `git init` + 提交，然后跑一次 `--mode audit`
  （不调模型，零成本），确认 INDEX.md 真的落到磁盘上，且**没有产生 status.json**。

**两种接入方式都要验**，因为「引用模式」的失败方式很特别 —— 它不报错，只是不工作：

- 引用模式（`--no-vendor`）**不能往别人仓库里塞 `scripts/`**，配置和目录要照常给
  （推断模块是这工具的价值，不能省）
- 判断「用的是哪种模式」必须**剔掉注释行** —— 两份 workflow 的头部都写了对方的示例，
  不剔的话会被自己的说明文字骗过
- doctor 要能认出模式，并且**不能因为「引用模式没有 scripts/」而误报**
- 装完就该能跑：模板里的 `uses:` 必须是真仓库地址，**发出去的模板不许带占位符**
  （测试直接读模板文件断言这一条）
- 人手改回去、或从带占位符的旧版本升上来，仍会留下 `uses: your-org/docwarden@v1`，
  Actions 就会直接找不到这个 Action。doctor 必须把它当阻塞项拦下 —— 这条护栏的测试是
  **注入**一个占位符来验，不依赖模板内容（否则模板一改，护栏就跟着失效了）

另外守住「模块推断」那条曲线：一个 `src/modules/` 下分了四个业务目录的项目，
必须切到 `src/modules/<业务>/` 那一层，**不能停在 `src/modules/` 上一锅端**。
`src/utils`、`src/components` 这种落空的兄弟目录要被补收成模块，`sourceRoots` 要取到
源码树顶层的 `src/`（取成 `src/modules/` 的话，巡检就永远发现不了新出现的目录）。

那条曲线本身还单独铺开测了（用纯函数喂文件清单，不碰磁盘）。它有两个**不报错、但结果明显不对**
的退化，都是实测踩到才发现的：

- **打分尺度不敏感**：分数只按文件数给，于是「12 个文件一锅端」和「切成 3 个各 4 文件的模块」
  完全同分，此时唯一的裁决者是层级惩罚 —— 而它偏向更浅。结果是一个
  `src/modules/{order,cart,auth}` 各 4 个文件的项目被压成 `src/` 一个大模块。
  现在每个「够格成模块」的组额外记一笔，让细分在不让任何组掉出可用区间的前提下胜出。
- **同分偏向更浅**：40 个文件挤在 `src/modules/` 时前缀被放宽到 `src/`。
  `src/` 会吞掉整个源码树 —— 之后新增任何目录都不再落空，巡检**永远不报警**，
  而「新目录漏配」正是最隐蔽的一类故障。现在同分时取更深、更具体的那一层。

同时守住反面：每个目录只有 2 个文件时不许切成碎片（否则会退化成鼓励切碎片）。

最后一条守的是一次**可能造成实际损失**的事故：**生成的配置里不许预填任何模型接口地址。**

工具的立场是「不替使用者决定源码发给谁」—— 填哪个 baseUrl 就等于把源码交给哪家。
如果模板预填了某家厂商的地址，一个没读文档的人跑起来会**直接成功**，然后在毫不知情的
情况下把整个仓库的源码发到一个公共站点去。所以两件事都要验：

- **配置留空**：源码文本里不许出现写死的接口地址或模型名，且必须是
  `process.env.LLM_BASE_URL || ''` 这种从空串起的写法。
  这里要**剔掉注释行**再判断 —— 模板注释里带了几种常见填法当参考，那是给人看的示例，
  不剔掉就会把自己的说明文字当成违规（第一版断言就中招了）。
- **开工前失败**：没配模型时跑生成必须非零退出、报错里说清「缺什么 + 两种配法 +
  也可以只跑 audit」，并且**一个文档文件都没写**（在扫仓库之前就停了）。
  同时验另一半：`--mode audit` 在没有模型、没有密钥时照常跑通 ——
  否则「零成本、随时可跑」就是句空话。

**配了模型之后还要验两件「看起来能跑、其实结果不对」的事**（场景十，真的调一次模型）：

- **功能清单的解析**。模型见过我们自己写进索引的 ` :: `，照着抄很常见；
  只认冒号的话说明会被切成 `: 创建订单`，而「按功能提问」正是靠这张表检索的。
  这是实实在在踩到过的 bug（`parseFeatures` 用 `search(/[：:]/)` 匹配到 `::` 的第一个冒号），
  修法是把「一条功能点怎么拆」收敛成 `splitFeature` 一处实现，读写共用。
- **生成溯源**。文档头部必须记下 `model` 和 `prompt_version` —— 否则换模型之后新旧文档
  混在一起，查不出「这批是哪个模型写的」。`prompt_version` 取的是提示词模板的**内容指纹**，
  不手工维护版本号（会忘），改一个字版本就变。同时反向断言：**接口地址不许写进文档**
  （那可能是内网地址），**密钥不许落盘**。

> 写这个场景时踩过一个坑：一开始用 `execFileSync` 跑被测脚本，而假模型服务就在
> **同一个 Node 进程**里 —— `execFileSync` 会阻塞本进程的事件循环，假模型永远收不到
> 请求，于是子进程等响应、父进程等子进程，**直接死锁**（表现是整个测试卡到超时被杀，
> 而日志停在场景标题那一行，没有任何报错）。凡是要一边跑服务、一边跑子进程，
> 必须用异步的 `execFile` / `spawn`。
>
> 另外这个场景**必须设 `timeout`**，不能只靠「不会死锁」这个口头保证：它里面有真实
> 的网络往返，子进程一旦卡住，整套测试会无限期挂住 —— 而挂住和失败的区别是，
> 挂住不给你任何线索。现在设成 90 秒 + `SIGKILL`，最坏情况也只是这一条失败、
> 且原因可读。收尾还要 `srv.closeAllConnections()` 再 `close()`：子进程被强杀时
> 它的 socket 可能还开着，只调 `close()` 会让**测试进程自己**等下去，
> 于是一条断言失败升级成「整个套件不结束」。

最后验一遍 doctor 的另一面：把 `src/modules/order` 改名之后，
必须报出「模块前缀指向不存在的目录」—— 这就是配置腐烂，**最危险的一类故障：
静默停更、不报错，只能靠主动巡检发现**。

### `ui-retry.test.mjs` —— 重试是否只补失败项

链条：jsdom 跑**真实界面代码** → 真实 `docwarden` 服务 → 假模型。

关键断言不是「最后都成功了」（那太弱），而是：

- 已成功模块的**耗时数字必须一字不变** → 证明它们没有被重跑
- 假模型的**调用次数**：`other` 恰好 3 次而不是 6 次 → 从服务端侧再次证明只有失败项被重跑

两条独立证据互相印证，避免「看起来对」。

### `status-lifecycle.test.mjs` —— 确定「人的确认」到底绑在哪

全程 11 步、20 条断言，核心要证明一句话：**确认绑定到具体那一版内容**。

其中两条最容易做错的：

- 源码改回去之后，确认应当**自动重新生效**（指纹是内容哈希，不是时间戳）
- 源码没变、只是正文被重新生成 → 确认**也必须作废**（换模型/换说法就是换了一份东西）

### `ui-persist.test.mjs` —— 刷新页面会不会白跑

三个 jsdom 实例：A 正常跑完 → B 只灌入 A 的会话（模拟刷新）→ C 灌入一个「有失败项」的会话。
jsdom 的 `localStorage` 不跨实例，所以用 `beforeParse` 手动注入——反而更贴近「刷新页面」的真实情形。

### `ui-status.test.mjs` —— 界面接线

每一步都点真的按钮，而不是直接调函数。这是为了防「界面写了、代码没接」那类问题。

### `mcp.test.mjs` —— MCP 服务

自己写了个最小 MCP 客户端，spawn 真实进程走真实 stdio 协议。专门查两件事：

- **stdout 必须全是合法 JSON-RPC**——MCP 的 stdio 模式下混进一行日志，协议流就废了。
  这个测试把收到的每一行都 `JSON.parse` 一遍。
- **状态确实跟着内容返回**——改掉源码后，MCP 必须当场报「已失效」。
  状态若不跟着走，前面整套状态机制就白做了。

### `no-secret-leak.test.mjs` —— key 不许落盘

界面上写着「你的 key 不会被写进任何文件」。这是给使用者的承诺，
而承诺最容易在后续改动中悄悄失效（加个字段、顺手存个 config，key 就跟着进 localStorage 了）。

所以测试塞一把特征鲜明的假 key，跑完整流程（扫描→生成→导出→人工确认），
然后**把项目目录下每个文件都读一遍**，再翻一遍 localStorage。
16 个文件、0 命中才算过。同时检查「流程确实跑完了」，
免得哪天流程断了、测试却因为什么都没写而假绿。
