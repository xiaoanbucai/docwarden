## 决策三问

> 三问不用全填。小改动填第一问就够；涉及架构、数据模型、对外接口的改动，三问都要有。

（现象 + 影响面。不要写「优化了性能」，要写「导出接口在 5 万行以上超时，运营每天手工分三次导」）

## 自动文档确认

> 合并后会由 CI 生成/更新模块文档。勾之前请**真的点开看一眼**预览评论。
> 这一步的价值：AI 出错时无人能审核，唯一的人为关口就是这里。

- [ ] 预览里**没有编造**代码中不存在的功能（**最重要的一项**——一句错误的「A 调用 B」比没有文档更危险）
- [ ] 预览里没有成段复述源码（那是把代码翻译成散文，等于制造第二份真相）
- [ ] 预览里的 `[待确认]` 标记，我知道需要谁来补
- [ ] 本次改动涉及的功能、模块划分与我对系统的理解一致
