选一个项目目录

建议第一次拿一个小项目试。比如自己的练习项目、组件库或小程序。
不要一上来就扫公司的大型仓库——先看清生成质量，再决定要不要用在正经项目上。

确认模块划分

模块是文档的最小单位。划得太细会让文档碎片化，太粗会让每次小改动都重生成一大堆。建议一个模块 5～30 个文件、1500 行以内。

接口和 key 都是使用者自己的，这个工具不代为提供。上面几个按钮只是帮忙少打几个字， 不填就用不了真实模型（演示模式不需要任何配置）。
两件事可以放心：你的 key 不会被写进任何文件——不落盘、不进导出的文档、 不进会话记录，关掉页面就没了。不放心的话就用一把只给这个用途的临时 key， 用完去厂商控制台吊销。
⚠️ 先把这条看完再填云端地址。填了 https:// 开头的公网接口， 就意味着你的源码会被完整发送到那家厂商的服务器上。本地模型 （127.0.0.1）不存在这个问题。
拿 sample/ 这种样例试没问题；公司项目的代码不要用云端接口跑， 除非你确认过公司安全规定允许。这个工具的设计前提就是「代码不出内网」，别在这里破了它。
关于等待时间。带推理能力的模型（名字里常见 reason / thinking / r1 字样）很慢—— 实测连 20 行的模块也要 2 分半，耗时主要花在推理上而非读代码。 换成不推理的模型通常快好几倍。另外：超时别低于 600 秒； 模块要切小，别指望一个大模块一次跑完；生成时进度条是逐行推进的，没有卡死，等着就行。
连本地模型有两个坑。一是地址要带 /v1 后缀；二是 ollama 默认不接受来自网页的跨域请求，需要先退出 ollama 再执行 set OLLAMA_ORIGINS=*（Windows）或 export OLLAMA_ORIGINS='*' 后重启。
本工具已经把请求放在本地服务里转发，所以更常见的问题是模型服务本身没启动。

文档现状
先扫描一个项目
为什么要有这一栏。生成的文档默认是候选——没人看过，不该被当成结论。 确认过之后才会变成已验证。之后只要源码或正文任一变过， 那条确认就自动作废：源码变了标已失效，正文重新生成则退回候选。 这样文档库就不会悄悄攒下一堆没人负责、也没人知道过没过期的内容。
