# MCP 服务永远只读，确认只能由人做出

docwarden-mcp 对 AI 编程助手暴露的知识库接口（概览、取文档、按文件找模块、搜索、查新鲜度）
**永远只提供读操作**。把文档标为「已验证」的动作只能由人通过本地界面或 `validate` 命令做出，
任何 AI 工具——包括未来版本的 MCP、包括 Agent 自己——都不获得这个能力。

背景：这套机制的全部价值在于"已验证 = 人背过书"。AI 编程助手是这个工具的头号用户，
如果它能在会话里顺手把文档标成已验证，就形成"模型自己生成、自己确认、自己信自己"的闭环，
状态章沦为装饰。这条边界挡的不是现在的恶意，是将来某个"给 MCP 加个确认工具能省事"
的好心提议——包括 AI 自己提的那种。

## Consequences

- MCP 新增工具时必须保持只读；任何写入意图一律指向 `validate` 命令，由人执行。
- 使用者想批量确认，也是人跑命令，而不是让 Agent 代劳。
- 本 ADR 的推翻需要新的 ADR 并明确说明信任模型变了。
